# Схема БД и миграции

## Правила

1. **`schema.sql` всегда отражает текущее состояние схемы.**
   Меняешь структуру — обновляешь `schema.sql` так, чтобы он с нуля
   создавал актуальную БД.

2. **Каждое изменение схемы — новый файл в `sql/migrations/`.**
   Имя: `NNNN_краткое_описание.sql`, где NNNN — 4-значный порядковый номер
   (`0001`, `0002`, ...). Сортировка лексикографическая, порядок = порядок
   применения.

3. **Миграции идемпотентны.** Используй `IF NOT EXISTS`, `IF EXISTS`,
   `ADD COLUMN IF NOT EXISTS`, `DROP CONSTRAINT IF EXISTS` и т.п. — тогда
   повторный прогон не сломается.

4. **Односторонние миграции.** Мы не пишем `down`-миграции: откат схемы в
   этом проекте не нужен. Если нужно откатить — новая миграция с обратным
   изменением.

## Порядок применения

`npm run db:init` смотрит на наличие наших таблиц:

- **БД пуста** → применяет `schema.sql` целиком, помечает все текущие
  миграции как применённые (чтобы потом их не дублировать).
- **БД существует** → прогоняет только недостающие миграции из
  `sql/migrations/`, пишет их в `schema_migrations`.

Флаг `--force-schema` заставит применить `schema.sql` даже к непустой БД
(использовать аккуратно — это не сброс данных, но может упасть на
конфликтах, если таблицы уже существуют с другим составом колонок).
